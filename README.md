# CubeTower — тестовое задание Unity Kids

2D-мини-игра: из бесконечной ленты кубиков внизу экрана игрок строит башню в правой верхней части
и выбрасывает кубики из башни в овальную дыру слева.

**Фактически затраченное время:** 3.5 дня

---

Все зависимости уже в проекте: Extenject, R3 (+ NuGet-зависимости в `Assets/Packages`), UniTask, DOTween (free),
Newtonsoft.Json, TextMeshPro, Odin Inspector (используется только в редакторе, не обязателен).
Ориентация альбомная. Проверка соотношений в Game View: 2340×1080 (19.5:9), 1920×1080 (16:9), 1440×1080 (4:3).

## Как играть

- Потянуть кубик в ленте **вверх** — взять его копию (лента бесконечная); **вбок** — прокрутить ленту.
- Первый кубик ставится в любое место правой части; следующие — только если отпустить их над башней:
  кубик подпрыгивает на вершину со случайным смещением не больше 50% грани.
- Мимо башни — кубик «взрывается».
- Башня растёт, пока последний кубик не вышел за верх экрана.
- Любой кубик башни можно в любой момент утащить в дыру (попадание — по овалу); верхние плавно опускаются.
  Отпущенный мимо дыры кубик возвращается на место.
- Каждое действие подписывается текстом над нижней частью экрана. Прогресс сохраняется автоматически.

## Соответствие требованиям

| Требование | Решение |
|---|---|
| 1. Масштабирование | Правила установки — цепочка `IPlacementRule` в модели башни. Новое условие = новый класс + строка в `TowerInstaller`. Пример «только на кубик того же цвета» — `SameColorAsTopRule` с тестом. |
| 2. Локализация | В коде только ключи (`LocalizationKeys`) → `ILocalizationService`. Реализация — таблица на ScriptableObject (RU/EN, язык устройства, запасной язык). |
| 3. Источники конфигурации | `IGameConfigProvider` (асинхронный контракт) → `GameConfig`. Реализация из ScriptableObject; JSON/сервер — новый класс без изменений в игре. |
| 4. Drag & drop со скроллом | Направление жеста определяется один раз в начале (`GestureClassifier`): горизонтальный — скролл, иначе — перетаскивание. Скролл получает события только если это скролл; отслеживается один палец. |
| 5. 19.5:9, 16:9, 4:3 | Разметка на якорях, `CanvasScaler` 1920×1080 match 0.5, фоны без искажений, размер кубика — доля высоты ленты, модель в «единицах кубика». |
| 6. Анимации | DOTween: прыжок по параболе, «взрыв», падение в дыру, опускание, надписи, шторка. |
| 7. Сохранение | Схема GameRepository / SaveLoader / SaveLoadManager, JSON-файл, AES-256 + HMAC, запись в фоне, атомарная замена файла, автосохранение. |
| 8. Графика | Графика макета в `Assets/CubeTower/Art`: фоны трёх частей экрана, овальная дыра, 20 спрайтов кубиков. |
| DI / Rx | Extenject + R3 (+ UniTask). |
| Крайние случаи | Битый/подменённый сейв → `.bak` и чистый старт; битый конфиг → понятная ошибка; повторный вход в модель запрещён; анимации отменяются и перенаправляются; второй палец игнорируется; сворачивание сохраняет игру и отменяет перетаскивание. |

## Архитектура

Луковая архитектура; слои — сборки (asmdef), зависимости только внутрь (проверяет компилятор).

```
CubeTower.Core            домен: Tower, правила, DTO сохранения (noEngineReferences — без UnityEngine)
CubeTower.Application     сценарии: машина состояний, сохранения, конфиг; интерфейсы внешнего мира
CubeTower.Infrastructure  адаптеры: ScriptableObject, JSON-файл, AES, лог, события Application
CubeTower.Presentation    MVP: View (MonoBehaviour), презентеры, твины, ввод
CubeTower.Composition     Zenject: инсталлеры, точки входа, загрузчик сцен
CubeTower.Tests.*         EditMode (модель, правила, сохранения, шифрование) и PlayMode (игра по ТЗ)
```

- **MonoBehaviour только на границе с Unity** — инсталлеры и View. Логика — обычные C#-классы из контейнера.
- **MVP (Passive View):** View пассивна; презентер подписан на модель и командует View; анимации — в `CubeTweener`/`FadeTweener`.
- **Модель → презентеры:** R3-потоки `Added / Removed / Reset`. **Презентер → модель:** синхронные команды `TryPlace / TryRemove`.
- **Запуск:** `ProjectContext` (глобальное) + сцена Bootstrap (`AppInitializer`) → `GameStateMachine`:
  `BootstrapState → LoadLevelState → LevelLoopState`. Игровая сцена не стартует сама (`Auto Run` выключен).
- **UI из префабов:** каждая часть экрана — префаб, `GameCanvas` — nested prefab; кубики создаются в рантайме из пула.
- **Потоки:** в фон уходят только операции над неизменяемыми данными (запись/чтение файла, шифрование, вывод ключа),
  продолжение возвращается в главный поток.

## Тесты

**Window → General → Test Runner.**
- **EditMode** (38): модель башни, правила, эллипс дыры, жест, валидатор конфига, сохранение, шифрование, файл.
- **PlayMode** (2, нужна сгенерированная сцена): игра через bootstrap с жестами через EventSystem по всем пунктам ТЗ
  и повторные броски с проверкой того, что видно на экране.
